## 二、被推翻的「伪缺陷」

### 2.1 经验条 / 负重条不是「永远满格」

**曾经的判断**：`ClientPortable/Shim/Mir176Hud.cs:299-315` 只设了 `Library/Index/Size`，
没有挂 `BeforeDraw`，所以条不会按比例裁剪，永远显示满格。

**实测推翻**：

截图取样（设备 2616x1140，逻辑 1024x768，`scale=1.484375, offx=548`）：

```
报告 等级=2 经验=14/200(7.0%) 负重=33/51
EXP 条：y=184 行，x=890..894 = (119,136,255)，x=896 起 = (24,16,16)  ⇒ 5/76 ≈ 7%
WGT 条：band y=213..221，x=890..938 是蓝色                ⇒ 49/76 ≈ 64.5%
```

7.0% × 76 = 5.3px、64.7% × 76 = 49.2px，**像素与数值吻合**。

**为什么能裁剪**：`Client/MirScenes/Dialogs/MainDialogs.cs:604-658` 里的
`ExperienceBar_BeforeDraw` / `WeightBar_BeforeDraw` 一直在跑（那是本项目自己加的补丁，
`git diff` 可见），用 `Library.Draw(Index, Rectangle{Size=Width*percent}, ...)` 做裁剪。

**结论：不要再改这两个条。** 相关素材事实：

- `Prguse.Lib` 全库只有 **一个** 76x13 帧（frame 7），是蓝→红竖向渐变的**满条**图。
- `Prguse3.Lib[291]`（800x251 底栏底板）在同一位置自带 `101018` 暗槽 ⇒ 只画填充段是对的。
- 「经验槽两条绿边」是伪需求：Prguse[7] 实测 0 个绿像素；1.76 原版
  `FState_utf8.pas:8909-8934` 也不画绿线。

**现象**（设备实测，2026-11-02 12:40）：

**排除法定位过程**：

1. 配置对不对？ —— 对。设备 `Configs/Setup.ini` 第 11 行 `Language=Chinese`；
   boot log 逐字：`[srv] 服务端配置：IP=0.0.0.0 Port=7000 语言=Chinese …`
2. 文件在不在？ —— 在。`/sdcard/Android/data/com.mir2.p2core/files/Localization/Chinese.json`，
   49871 字节，第 69 行就是
   `"ChatBanRemainingTimeByMinutes": "你被禁止聊天，还有 {0} 分钟 {1} 秒。"`
3. 路径对不对？ —— 对（2026-11-01 已把 `".\Localization\"` 改成 `Path.Combine`，
   见 `Server/Settings.cs:631-637`）。
4. ⇒ 只剩一种可能：**JSON 反序列化失败**。

**根因**（`Shared/Language.cs:4189-4225`）：

